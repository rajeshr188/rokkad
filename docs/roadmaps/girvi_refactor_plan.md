# Girvi Refactor Implementation Roadmap

This roadmap converts the deep audit in [Girvi Deep Analysis](../audits/girvi_deep_analysis.md) into a phased implementation plan. The order is intentional: protect money, collateral, lifecycle, tenant, and audit correctness before architecture cleanup or UI redesign.

Do not execute phases as one large rewrite. Each task should be a small verified slice with focused tests.

## Phase 5: Accounting Integration Readiness

Goal: define clean adapter points and event contracts without implementing the accounting cutover.

Girvi should own loan domain state, source documents, collateral state, notices, and workflow decisions. DEA should own voucher creation, voucher posting, journal entries, ledger lines, period locks, reversals, idempotency enforcement for accounting records, and accounting reports.

Girvi events that should produce accounting vouchers:

| Event | Source in Girvi | Expected DEA responsibility | Adapter point |
| --- | --- | --- | --- |
| Loan disbursed | `GivenLoan` transition to `ActiveCurrent` | Cash/bank credit, borrower loan receivable debit | `integrations/dea_adapter.py`, future event publisher |
| Taken loan activated | `TakenLoan` transition to `Active` | Cash/bank debit, lender loan payable credit | Same adapter |
| Given loan repayment received | Repayment command | Cash/bank debit, principal/interest receivable credit split | Repayment service adapter |
| Taken loan repayment paid | Taken repayment command | Lender payable debit, cash/bank credit, interest if applicable | Repayment service adapter |
| Interest accrued | `LoanInterestAccrual` batch | Interest receivable debit, interest income credit | Accrual adapter |
| Loan released/closed | `Release` source document | Receipt posting and source traceability; no direct collateral GL unless policy requires | Release adapter |
| Renewal | `LoanRenewal` source document | Receipt for paid amounts, disbursal/top-up/carry-forward accounting as defined | Renewal adapter |
| Auction recovery | Future `AuctionCase`/recovery document | Recovery receipt, gain/loss/write-off as configured | Recovery adapter |
| Collateral sale | Future `CollateralSale` document | Sale proceeds, recovery, expense, surplus/shortfall accounting | Recovery adapter |
| Write-off | Write-off approval/source document | Loss recognition and receivable write-off | Write-off adapter |
| Reversal/correction | Reversal command | Reversing voucher and journal entry | DEA reversal facade |
