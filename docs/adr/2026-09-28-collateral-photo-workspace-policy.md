# Workspace collateral photo policy

The owner requested optional-by-default collateral photographs and selected
mandatory enforcement at approval, while allowing incomplete drafts.

Use a single Loans-owned `LoanOriginationSettings` record per Workspace. Missing
configuration means optional. The existing setup-administration permission gates
changes; ordinary services audit the previous/new value and actor. Migration
0028 adds a directly Workspace-owned table with forced RLS and registry coverage.
This operational rule is independent of financial valuation/interest policies.

Approval checks every item's usable photo when mandatory, including renewal
successors, and freezes the applied boolean in its immutable payload. Subsequent
settings changes do not rewrite approvals. Drafts always accept absent photos;
positional upload slots retain their item association when another row has none.
Blank legacy images do not satisfy the mandatory rule.

For approvals explicitly recording optional photographs, an absent collateral
photo leaves the ticket frame empty even if an older template marks the frame
required. The document media evidence carries that opt-in choice. Unreadable or
checksum-mismatched selected photographs still block printing. Historical payloads
without the new rule preserve existing template behavior; issued PDFs are never
regenerated by a setting change. Borrower-photo rules remain independent.

This supersedes the unconditional photo requirement in the mixed-metal
origination contract. No financial records, loan terms or custody evidence are
changed by the setting.
