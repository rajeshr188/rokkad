# Snapshot-bound Linode replay package

The owner accepted the three-Workspace browser rehearsal and requested repeatable
preparation. Preserve its reviewed inputs in a checksummed private package and
compose the existing Party, legacy opening and closed-history services through
`linode_migration`. Rebind destination IDs in clean Workspaces; retain source IDs,
approved financial facts and source evidence. Normal authorization, restricted
runtime RLS, source validation and signed per-loan approval still apply.

Use an existing audit entry as the atomic Workspace/setup checkpoint. Existing
import identities and hashes supply retry behavior. Admission and reconciliation
are separate commands; successful insertion alone never means production-ready.
No new persistence model or migration UI is introduced.

A package is approved for exactly one archive checksum. A fresh dump must be
compared and newly prepared; approval of old balances does not approve changed
customers, loans, payments, releases or a later cutover date. This package is not
a live synchronizer or an automatic financial-decision generator.

Production media is on the same Linode filesystem, not R2. The SQL archive and
this replay package do not contain the photographs/documents. Separate inventory,
backup, checksums, source associations and destination verification are required.

See [the operator runbook](../implementation/linode-reviewed-replay.md).
