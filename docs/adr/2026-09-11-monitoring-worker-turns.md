# ADR: Bounded Workspace turns and per-loan monitoring transactions

The owner prioritized capacity hardening for 3,000-10,000 active loans per
Workspace and at least 100 Workspaces. This refines the worker portion of
[complete monitoring](2026-09-11-complete-loan-monitoring.md); projection,
financial and immutable policy contracts are unchanged.

## Decision

The command calls a worker-only `reassess_pawn_loans_pass`. It rejects a surrounding
transaction or Workspace context, selects at most the configured batch size, then
opens a fresh `workspace_context` for each candidate. Each loan is rechecked and
claimed using `SELECT FOR UPDATE SKIP LOCKED` before calculation. Its lock lasts
through source fingerprint checks, projection/transition writes and commit. The
next loan cannot prolong a previously processed loan's lock.

Candidate selection is advisory: a loan that another worker refreshed, closed, or
locked is skipped on recheck. Each candidate is attempted at most once per pass.
Crashes roll back the current loan; earlier commits survive and unfinished loans
remain due. There is no lease released before calculation, external queue, Redis
dependency or new persistent claim model. The existing transaction-local RLS
context API is unchanged. ACTIVE Workspace lifecycle is revalidated at each loan.

The existing in-context batch service remains available for the bounded UI action;
its transaction semantics are unchanged. It now accepts an optional explicit loan
candidate subset, still applying Workspace, ACTIVE, currentness and lock checks.

The command accepts one or more explicit Workspace IDs. Every round gives each
configured Workspace one bounded turn, in supplied order; duplicates are removed.
A Workspace failure does not prevent another Workspace's turn. There is no global
tenant enumeration and no new staff or license scope. Operators can partition
explicit Workspace lists between a bounded number of processes; aggregate worker
concurrency must still be measured before production sizing.

Repeated mode sleeps `--busy-seconds` (default 1, range 1-60) after a round with
successful assessments. A round with no successes uses `--repeat-seconds`
(60-86400): empty portfolios and error-only workloads do not spin. This changes
the previous unconditional five-minute pause. One-shot mode processes one turn
per configured Workspace and fails if any assessment or Workspace turn fails.
Dates are recomputed before each repeated turn; fixed `--as-of` remains one-shot
only. No borrower communication or financial event is generated by monitoring.

## Evidence and limits

Restricted-role tests verify committed visibility and NOWAIT access to the first
loan while the second is processed, no cross-Workspace projections, unset-context
denial, error isolation and competing workers. Command tests cover round-robin
turns, partial failures, busy/idle pauses and date rollover.

The mixed benchmark includes all four supported repayment structures, 7-400-day
loan ages, 1-4 gold/silver items, repayment/reversal history and closed loans. It
measures a committed worker pass as well as the older in-context batch. These
are local synthetic measurements, not 100-Workspace production acceptance. Full
load, backlog/freshness targets, foreground p95/p99 latency and recovery under
rate bursts remain required. See [the results](../implementation/rates-appraisal-monitoring-review.md).
