# Bounded owner decisions for migration exceptions

The owner resolved specific Linode source exceptions after inspecting the rehearsal.
Reuse the existing Party review and Loans signed staging boundaries; do not weaken
ordinary duplicate detection, source validation or immutable financial provenance.

## Distinct addresses

An authorized child-import operator can review 1–1,000 selected source address IDs
in an unfinished, validated batch with a bounded reason. The service locks the
Workspace and batch and requires the current approval digest. Each source ID must
identify one row. Its decision binds the canonical row hash, exact resolved parent
and current set of matching destination address IDs. Revalidation rejects source,
parent or matching-address drift. Within-batch matching text is allowed only when
both rows have decisions; duplicate external IDs and competing defaults still fail.

Decisions generate warnings and a new preview; ordinary acknowledged commit remains
required. They preserve text and portable identities, are audited and cannot be
saved as mapping presets. Reuse the existing batch mapping JSON and forced RLS;
no new table, generic conflict override or automatic merge is introduced.

## Excluded source payments

The legacy opening adapter continues to reject payment-bearing loans by default.
An explicit operator-supplied decision may exclude payments only for a registered
versioned source profile, matching archive hash, selected loan ID and raw loan hash,
and the complete map of actual payment IDs to raw row hashes, plus a bounded reason.
The original payment records and decision remain in immutable staged source evidence
and export. Signed approval covers that evidence. The browser explicitly displays
the exclusion and payment IDs; the command supports `--payment-review-file` and
still only stages. Unchanged principal and every other admission rule still apply.

The September 21 owner decision excludes 14 loans' source payments. Exactly one is
in the owner-reported closed cohort and 13 remain outstanding. Preserve the earlier
question's erroneous “12” and the explicit source-count correction. No payment events
are created, and no source records are deleted. Fresh snapshot evidence must be
re-extracted and decisions rebound; this is not incremental snapshot import.

## Corrections and non-operational entries

New `linode-jsk/2` and `linode-lakshmi/2` profiles apply exactly six source-item purity
corrections to 100%, checking original values and retaining correction ledger `/2`
and raw row hashes. The old `/1` profiles and accepted documents stay unchanged.
Unlisted invalid values remain errors. Source release evidence always controls
opening eligibility; the owner's custody confirmation was conditional on its absence.

The 190 inactive-customer loans are retained through the existing closed-evidence
service as owner-reported closed, with zero reported balance and unknown release
dates. Raw graphs and the owner decision remain attached; no settlement history is
fabricated. WH01223 is a zero-principal entry without items or release, confirmed
unused/cancelled. Preserve its raw graph and exclusion in the private migration
manifest; create neither an operational loan nor a historical closure claim.
