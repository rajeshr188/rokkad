Loan document printing guide

Layouts, physical print profiles, official issues, and safe recovery for Owners and Admins.

Print profilesDocument layouts
The safe workflow: Design and publish logical content → create and test a physical print profile → assign both → use the normal loan Print button → verify the immutable issue evidence.

Understand the LPD7 boundary

Document layout owns
  • Legal wording, fields, tables, signatures, and QR
  • Original, Duplicate, Terms, and D3 logical surfaces
  • Flow geometry or exact PDF-overlay backgrounds
Print profile owns
  • A5 sequential or A4 landscape side-by-side packaging
  • Simplex/duplex page order and selected logical surfaces
  • Scaling, flip-edge, and printer guidance

Changing paper or duplex packaging does not require cloning the legal layout. Published layout and profile revisions are immutable.

1. Create your first layout

  1. Select Create starter layout on the layouts page.
  2. Give it a clear name, such as Main Counter Loan Ticket, and choose the document type.
  3. Use the generated starter definition. Change only the wording, blocks, page settings, and registered bindings you need.
  4. Save the draft, then preview it with a representative loan or event.
  5. Test-print on the actual paper and printer before publishing.

2. Publish and assign the layout

Publishing freezes a revision. If it later needs correction, clone it to a new draft; published revisions cannot be edited.

Choose the narrowest assignment that matches the business need:

  • Workspace: default for all licenses and series.
  • License: overrides the workspace default for one license.
  • Series: overrides both for one series.

Resolution order: Series → License → Workspace → built-in fixed PDF.

3. Create, test, and assign the loan-ticket print profile

  1. Open Print profiles and create a draft.
  2. Choose A5 or A4 side-by-side packaging, simplex or duplex, scaling, and printer guidance.
  3. Preview and download a test print using a published logical layout and an approved sample loan.
  4. Publish the validated draft, then assign it to the workspace or one Series.

Profile resolution: Series → Workspace → built-in A5 Original + Duplicate. A Series-specific profile wins. Assignment is rejected if the effective layout cannot supply every surface required by the profile.

4. Print and inspect official evidence

Staff continue using the existing Print/PDF actions on the loan, repayment, release, auction, and renewal screens. Loans resolves the applicable published layout and, for configurable loan tickets, the physical print profile.

The first official issue is stored exactly. Open Issued documents to inspect its layout/profile revisions and hashes or download the exact stored PDF. Later reprints return those same bytes even if assignments change.

Logos, backgrounds, QR, and copies

  • Add PNG/JPEG logos or backgrounds, or a valid bounded PDF background, to a draft revision and reference its asset key in the definition.
  • Use the registered document.verification_id binding for the official QR code.
  • Copy modes support single, original/duplicate, and original/duplicate duplex output. Duplex also requires back-page blocks.
  • Only registered blocks and bindings are allowed; HTML, Python, model paths, and template code are rejected.

Flow v2 design containers

  • Section: groups related blocks with plain, outlined, or tinted presentation.
  • Columns: places two to four groups side by side using widths that total 100 percent.
  • Field grid: presents registered fields in a compact one-to-four-column grid.

Containers still participate in automatic flow; they do not provide X/Y coordinates or fill boxes on a background PDF.

Tables and repeating page regions

  • Tables can select payload columns, rename headings, assign percentage widths, align values, repeat headings, and use grid, minimal, or striped presentation.
  • Bounded headers and footers repeat compact titles, fields, images, QR codes, verification details, or spacers on every page.
  • Region height is reserved outside the body. Oversized or unsupported region content fails validation or rendering.

Formatting, conditions, and overflow

  • Values can use approved case, ISO-date, and plain-decimal formats.
  • Optional presentation can use present, empty, equals, or not-equals conditions over registered fields.
  • Mandatory fields, tables, and verification cannot exist only inside conditional blocks.
  • Long values must explicitly wrap, shrink after a character threshold, or fail rendering.

Visual Flow editor

Open any Flow schema-v2 draft and select Visual Flow editor. You can change page/theme settings, reorder or remove top-level blocks, and add common field, grid, section, field-plus-QR, spacer, page-break, and signature blocks.

Preview and test-print directly from the editor. Advanced JSON remains available for detailed tables, page regions, conditions, overflow, and deeply nested composition; both surfaces update the same validated draft.

Exact PDF overlay mode

Choose Exact PDF overlay when creating a layout for an existing form. Upload its PDF background with asset key form.background, then position registered fields using whole-millimetre rectangles measured from the page's top-left corner.

Use the Visual overlay editor to see the background, drag rectangles, enter exact geometry and properties, and add/remove blocks. Advanced JSON remains available for detailed tables, conditions, formatting, overflow, and duplex back pages.

Sheet composition

Loan-ticket layouts define separate Original front, Duplicate front, Original Terms, and Duplicate D3 logical surfaces. The print profile decides whether those surfaces become sequential A5 pages or Original/Duplicate imposed side by side on A4 landscape.

Blocks may apply to Both, Original only, or Duplicate only. Required front evidence is checked for every generated copy, and a duplex profile cannot be assigned when required Terms or D3 surfaces are absent. Older published layouts retain embedded composition only for explicit legacy recovery.

Moving or correcting a design

Correction: clone the published revision, edit and test the new draft, publish it, then replace the assignment. Retire the old revision only after confirming the new assignment.

Move between workspaces: export a sanitized pack, import it into the destination, then review, preview, publish, and assign it there. Imports are always unassigned drafts.

If a print fails

  1. Open Integrity diagnostics.
  2. Clone and correct the defective layout or profile revision; do not alter stored issue files.
  3. For a loan-ticket packaging problem, an Owner/Admin can explicitly add ?print_profile=legacy to use the published layout's embedded composition. Runtime never selects this silently.
  4. For urgent fixed-renderer recovery, an Owner/Admin can add ?renderer=fixed to the normal PDF URL. Both recovery paths are audited.
  5. Before production use, physically test A4/A5, simplex/duplex, long names and tables, regional text, backgrounds, margins, signatures, and QR scanning.
