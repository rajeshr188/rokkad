1. Choose a layout and create a draft

In the required Workspace, open Settings → Documents & printing → Document layouts. Setup is for Owners and Admins. You will need an approved PawnLoan in this Workspace to preview loan tickets. Use a representative existing loan; creating a real loan solely as dummy print data is unnecessary.

A layout defines what appears on one document: wording, borrower fields, collateral, signatures, and background. A print profile arranges loan-ticket copies on physical pages and controls PDF scaling. Profiles currently apply to loan tickets; layouts also support repayment receipts, release memos, auction documents, and renewal agreements.

2. Prepare, upload, and select an overlay background

Prepare a clean blank form containing static headings, lines, and wording. Remove example borrower names, amounts, and signatures: anything baked into the file will appear on every print. Export a PDF at the intended page size; if scanning paper, straighten it and remove unwanted borders. Start with a single-page PDF for one copy.

The upload supports PDF backgrounds up to 10 MiB and 4 pages, or PNG/JPEG images up to 5 MiB and 20 million pixels. A multi-page PDF does not automatically map its pages to Original, Duplicate, Terms, and D3. Separate one-page files are easier to configure and verify.

  1. On the draft revision page, find Assets. From the overlay editor, return using Assets, JSON, and publishing.
  2. Enter Key = form.background, Kind = Page background, and choose your PDF in File.
  3. Select Validate and upload. Confirm the key appears in the Assets list. Assets belong to this revision; uploading to another layout will not make them available here.
  4. Open Visual overlay editor. In Logical page and backgrounds, check Shared logical background is form.background, then select Save settings.

The starter already references form.background, so uploading with that exact key satisfies its default reference. If you use another key, select that key explicitly in the editor. Uploading a file alone does not change an existing selection. A key is an internal name, not a filename or URL: start with a lowercase letter, then use lowercase letters, digits, dots, underscores, or hyphens (64 characters maximum).

For a replacement background, upload under a new key such as form.background.v2 and select it; there is no replace-file control. For a logo, upload a PNG/JPEG as Image / logo with a key such as brand.logo, then reference that key in an Image block. Uploading a logo does not automatically place it on the page.

3. Match the page size and position fields

New overlay starters use A4. Begin with an A4 background to learn the editor without changing the starter geometry. For exact physical alignment in a loan-ticket profile, design an A5 logical page instead: A5 profiles and each half of the A4 landscape profiles use an A5 copy. Do not upload an already combined A4 Original/Duplicate form as one copy.

Choose Logical surface size to match the background (A4: 210 × 297 mm; A5: 148 × 210 mm). Changing this setting does not automatically resize existing blocks. When converting the A4 starter to A5, first reduce/reposition all blocks, including tables, verification, and signatures, to fit inside A5, saving each change; then change the page size and save settings. Otherwise validation can reject rectangles outside the page.

Coordinates are measured from the top-left corner of the logical page. X moves right; Y moves down. Width and Height describe the space reserved for a block. Use whole millimetres. Font size is in points, not millimetres.

  1. Find the existing field block for the value you want. Its Binding identifies the loan data supplied at print time; keep the starter binding unless you know the replacement is registered. Do not enter an actual customer's name as fixed Text.
  2. Drag its rectangle near the target box, or enter the measured X/Y/Width/Height values in that block's controls.
  3. Select Save block for that block. Dragging only changes the form inputs; it does not save. Save before editing another block or reloading.
  4. Use Preview PDF to check real text, wrapping, and tables. The canvas rectangles are positioning aids, not the final printed text.
  5. Repeat for the remaining required fields, collateral table, verification, and signatures. Use Add overlay block for additional content. Do not remove required evidence merely to make a small form fit.

Check a long name, several collateral rows, regional text, and signature space. Detailed table columns, overflow rules, conditions, and back-page blocks use Structured layout definition on the revision page, followed by Validate and save draft. The visual editor does not expose every advanced setting.

4. Configure Original, Duplicate, and back pages

A surface means one face of one copy. The four loan-ticket surfaces are Original front, Duplicate front, Original Terms (the Original back), and Duplicate D3 (the Duplicate back).

  1. For identical fronts, keep the shared background. For different forms, upload each as Page background, using distinct keys such as form.original, form.duplicate, form.terms, and form.d3.
  2. In the overlay editor, select each key in its matching background dropdown and select Save settings. A surface-specific selection overrides the shared background; a blank selection falls back to the shared one.
  3. Use a front block's Copy scope to show it on Both copies, Original only, or Duplicate only. Save each changed block.
  4. Start with simplex (fronts only). Before selecting duplex, supply and preview the Terms and D3 surfaces, including any required back-page content. A shared background alone does not establish the required back surfaces: select explicit Terms/D3 backgrounds or supply back-page blocks. Advanced back-page content is configured through back_blocks in the structured definition, not by adding another front block.

Editor limitation: the canvas shows the Original front background's first page and front blocks. It is not a four-surface editor. Inspect Duplicate, Terms, and D3 in the print-profile PDF preview. A back background is static artwork; uploading it does not create dynamic back-page fields.

5. Publish the layout, then create and preview a print profile

Once the layout preview looks correct, return to its revision page and select Publish and freeze. Publishing makes the revision available for profile previews; it does not assign it as the counter default. To change a published layout, use Clone to new draft.

  1. Open Print profiles → Create print profile. Give it a useful name such as Counter A5 fronts.
  2. Choose a Composition from the table below, Scaling policy, Flip edge guidance, and optional Printer guidance. Select Create validated draft.
  3. On the profile revision page, under Preview and test print, select your published logical layout and an approved sample loan. Select Preview PDF or Download test print. These previews are watermarked and do not create official issued documents.
  4. Correct profile settings with Validate and save draft. When the PDF is ready, test it on the intended printer and paper before production use, then select Publish and freeze.

Fit proportionally to the profile slot scales the whole logical page, including background and fields, to fit. This is a practical first example with an A4 starter and blank paper, but it changes physical distances. Actual size (layout page must match) requires a matching logical page; use A5 for these profiles. An A4 logical page with Actual size will be rejected.

PDF scaling and printer scaling are separate. In the PDF viewer/printer dialog, use the output paper size and 100%/actual-size printing to avoid a second fit-to-page adjustment. Set duplex and flip edge in the printer dialog as needed: profile guidance does not control the driver or enable automatic duplex. Background artwork is included in the PDF; there is no background-on-screen-only toggle for preprinted stationery. Complete physical alignment checks later if a printer is unavailable.

6. Assign both defaults and use normal Print

  1. Open the published layout revision. Under Assign default scope, leave License and Series blank for the Workspace default, select License for its default, or select Series for one numbering series. Select Assign layout.
  2. Open the published print profile revision. Leave Series blank for the Workspace default, or select the same Series for a limited rollout. Select Assign print profile. Profiles have no License-level assignment.
  3. Open an eligible loan and use its normal Print/PDF action. Inspect the resulting pages and Issued documents for the recorded layout and profile revisions.

A Series-specific layout overrides a License default, which overrides the Workspace layout. A Series-specific profile overrides the Workspace profile. Check both when an unexpected design appears. Assignments are validated against compatible layouts and required surfaces; publication alone does not make an incompatible pair usable.

Existing official PDFs stay unchanged. Reprinting an already issued document returns its stored PDF, even after changing defaults. Use preview while designing; evaluate new defaults on a document that has not yet been officially issued. For later corrections, clone, edit, preview, publish, and assign the new revision. Never edit stored issue files.
