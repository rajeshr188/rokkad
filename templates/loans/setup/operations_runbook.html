PawnLoan support runbook

The new Loans app remains feature-hidden. Girvi continues to own production navigation and every legacy loan until the controlled Phase 6 gate.

Failed accounting delivery

  1. Open the reconciliation report and confirm the source event/outbox payloads agree.
  2. Correct the displayed DEA period, ledger, or Party-account setup blocker.
  3. Use Queue retry once. Never create a voucher or journal manually.
  4. Confirm the event becomes Posted and its DEA references reconcile.

Sequence or license blocker

  1. Open the linked license setup.
  2. Expired/inactive licenses remain attached to existing loans but cannot issue new loans.
  3. If a sequence is exhausted, create or select a new active series; never reset or reuse committed numbers.
  4. Both pawn-loan and release sequences must be ready.

Reversal and custody problem

  1. Use the reconciliation report to identify the newest unreversed dependent event.
  2. Reverse events strictly newest-first with an administrator reason.
  3. Never edit posted DEA records, immutable releases, accruals, or custody history.
  4. If physical custody differs from the system, stop servicing and escalate; do not force a reversal.

Deployment and rollback

Tenant migrations must use migrate_schemas. Before enablement, run migrations, checks, the E5.5 end-to-end suite, and reconciliation. Rollback means disable future Loans navigation/creation and redeploy the previous compatible code; never delete Loans records or mutate posted accounting. Existing new-app loans remain owned by Loans and must still be serviced there.

The detailed command and verification checklist is maintained in docs/implementation/pawn-loan-mvp-operations-runbook.md.
